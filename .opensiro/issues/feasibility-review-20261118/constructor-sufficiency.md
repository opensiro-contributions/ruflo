## 1. Boundary, user counterfactual and authority

**System in focus:** supported first-party Ruflo v3/meta-harness Codex or Claude orchestration in one operator-governed workspace; original code and standard distribution only. Independent RVM, MetaHarness, a private plugin, a research-only ADR or human maintainers **outside** the first-party decision-owner boundary are not credited as installed Ruflo actors.

**User task:** operator submits a tool-using task whose constraints conflict with current environment/evidence. For an irreversible/high-risk action, a genuinely independent reviewer must see the contradiction, choose a permitted correction (hold/ask/continue only on new evidence), and observe whether downstream tool dispatch actually obeys. **Counterfactual:** remove the independently composed reviewer while keeping policy and execution transport; if an unchanged deterministic rule makes the same organizational choice, no new S3*=C constructor witness exists.

**Authority:** user and host/RVM retain effect permission; feasibility evidence grants **zero** capability (`authority:none`). An independent reviewer may propose/decide review disposition **within delegated correction scope** but never override hard permission, policy, origin trust, runtime capability or S5 decisions. Relevant PR/issue does not transfer reviewer authority.

**Current decision:** **NO_GO** for implementing this hypothetical S3* C path. [Original #3191](https://github.com/ruvnet/ruflo/issues/3191) human triage explicitly needs maintainer architecture/threshold decisions; RuV reproduction is pending. Missing positive proof must not be called shipped C.
